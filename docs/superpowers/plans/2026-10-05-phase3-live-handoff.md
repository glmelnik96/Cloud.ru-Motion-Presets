# Задание локальному агенту: живые проверки панели BrandKit в After Effects и Premiere

**От кого:** облачная сессия Claude, ветка `claude/determined-cannon-eum3ei` (2026-10-05).
**Кому:** агент Claude Code на ПК сборки, где стоят AE 26.5 и Premiere 26.5.2 и рабочая папка `C:/CRBK/work`.
**Зачем:** в облаке нет Adobe-приложений. Там написаны ядро панели, мост и адаптеры хоста, они проверены только на фейках объектных моделей AE и Premiere. Нужен прогон в настоящих приложениях и отчёт, по которому облачная сессия исправит ошибки.

## Что уже сделано в ветке

| Часть | Где | Что делает |
|---|---|---|
| Ядро панели (TypeScript) | `panel/src/core/` | читает `library.json`, выбирает вариант по кадру, строит форму и запись полей, считает длину вставки (time remap по C27, обрезка `trim`), проверяет шрифты и цвет, планирует вставку |
| Мост | `panel/src/bridge/bridge.ts` | `host.call()`: ASCII-JSON, очередь, таймауты, повтор при холодном старте только для чтения |
| Адаптеры хоста (ES3) | `panel/host/common.jsx`, `ae.jsx`, `pr.jsx` | `getContext`, `checkFonts`, `insertItem`, `probeInsert`, `readFields`, `diag` — по приёмам, проверенным в S3 и S5 |
| Каталог | `tools/library/build-catalog.mjs` | `library.src.json` + выходы конвейера → корень библиотеки с `library.json` |
| Живые проверки | `tools/panel/live.mjs`, `tests/live/` | всё перечисленное в настоящем хосте через dev-панель (CDP 8094/8096), отчёт JSON |

## Шаги

1. Получить ветку и зависимости:
   ```bash
   git fetch origin claude/determined-cannon-eum3ei
   git checkout claude/determined-cannon-eum3ei
   git pull origin claude/determined-cannon-eum3ei
   npm ci
   ```
   В `package.json` добавлены `typescript` и `preact`. Если скачивание npm-пакетов на этой машине нужно согласовать с пользователем — спросите его перед `npm ci`.
2. `npm test` — всё зелёное (≈ 560 тестов). `npm run typecheck` — без ошибок. Если что-то красное — остановитесь и пришлите вывод.
3. Условия перед прогоном:
   - AE 26.5 и Premiere 26.5.2 запущены, в обоих открыта панель **BrandKit Dev** (Window → Extensions), как для мастеров. Проверка: `node tools/host-run.mjs --host ae "JSON.stringify({ v: app.version })"` и то же с `--host pr`.
   - В AE открытый проект сохранён (нет несохранённых изменений): прогон создаёт новый черновой проект `C:/CRBK/work/panel-live/ae/panel_live.aep`, а грязный проект пользователя отказывается закрывать.
   - Упакованные мастера первого пакета лежат в `C:/CRBK/work/build/<id>/`: `<id>_v1.aep` и `mogrt/<id>_<формат>_v1.mogrt` для `LOGO_Shot`, `LOGO_Mark`, `TTL_LowerThird`. Если их нет: `node tools/masters/package.mjs --item <id>` для каждого (нужен AE).
4. Прогон:
   ```bash
   node tools/panel/live.mjs --host ae
   node tools/panel/live.mjs --host pr
   ```
   Каждый прогон сам собирает каталог в `C:/CRBK/work/panel-live/library`, грузит пакет хоста через `$.evalFile` (это и есть проверка холодного старта моста), создаёт композиции или секвенции всех вариантов и вставляет каждый вариант дважды: A — длиной шаблона, B — на 4 с длиннее. Затем читает поля новым вызовом, сравнивает кадры A и B на входе и уходе (SSIM ≥ 0,98), проверяет ближайший вариант для 2560×1440, отказ при смене активной композиции или секвенции, один шаг отмены, а в Premiere — выбор дорожек и добавление V4 через QE.
   Если хост показал модальное окно или прогон оборвался исключением — **не перезапускайте вслепую**. Сначала `node tools/host-run.mjs --host <ae|pr> "JSON.stringify({ v: app.version })"`, опишите, что было на экране (скриншот, если можно), и только потом решайте, запускать ли снова.
5. Просмотр глазами (5 минут):
   - AE: в `C:/CRBK/work/panel-live/ae/panel_live.aep` пройдите композиции `LIVE_*`: тексты кириллицей, плашки, вход и уход у длинного экземпляра B;
   - Premiere: в `C:/CRBK/work/panel-live/pr/panel_live.prproj` — секвенции `LIVE_*`, клипы на V2–V4, поля в Properties.
   Запишите всё, что выглядит не так.
6. Вернуть результаты:
   - закоммитьте **только** `docs/research/panel-live/ae-report.json` и `docs/research/panel-live/pr-report.json` (ничего из `C:/CRBK/work`), сообщение `test(panel): live run in AE and Premiere 2026-10-xx`, и `git push origin claude/determined-cannon-eum3ei`;
   - в ответе пользователю: по каждому хосту «прошло / всего», список упавших проверок с `detail`, проверки с пометкой `info`, заметки из просмотра, версии Node, AE и Premiere.

## Чего не делать

- Не чините код в `panel/` — опишите ошибку, исправит облачная сессия. Исключение: сам харнесс упал до проверок по очевидной локальной причине (например, путь к пресету Premiere: переменная `BRANDKIT_PR_ROOT`). Тогда минимальная правка, и она отдельной строкой в сообщении коммита.
- Не трогайте проекты пользователя и `C:/CRBK/work/build`. Не удаляйте выходы прошлых прогонов вручную: прогон перезаписывает их сам.
- Проверка «undo» помечена как информационная: номер команды `16` в AE и `qe.project.undo()` в Premiere не из документации. Её провал не блокирует, но сообщите, что произошло.
