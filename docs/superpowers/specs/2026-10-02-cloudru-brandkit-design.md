# Cloud.ru BrandKit — дизайн-спецификация

**Дата:** 2026-10-02 · **Статус:** разделы утверждены в брейншторме; внесены итоги поздних проверок и ревью спецификации (73 замечания, см. `2026-10-02-cloudru-brandkit-review.md`) — ждёт финального ревью

**Цель.** Превратить набор AE-проектов «Граф пакет Cloud.ru» в понятную систему шаблонов и эффектов и дать видеокоманде одну панель в After Effects и Premiere Pro. Через неё бренд-элементы, шаблоны и пресеты анимации вызываются кнопкой, без ручного импорта проектов.

**Термины.**
- **Первый пакет** — логошоты и титры: с них начинаются фазы 1–2.
- **Пилот** — работа 2–3 монтажёров на живых проектах (фаза 4).
- **Ядро** — TypeScript-логика панели без привязки к хосту.
- **Адаптер** — ExtendScript-код конкретного хоста.
- `library.json` — каталог библиотеки; `CSXS/manifest.xml` — манифест CEP-расширения.

## 1. Исходные условия и принятые решения

| Вопрос | Решение |
|---|---|
| Кто пользуется | Видеокоманда Cloud.ru: монтажёры и моушен-дизайнеры, Windows и Mac |
| Хосты | After Effects и Premiere одновременно, одна панель с общим каталогом |
| Доставка библиотеки | Внутри установщика плагина; новая версия шаблонов = новая версия установщика. Сам плагин лёгкий. Вес библиотеки считается в фазе 0 и ограничен бюджетом установщика (D24); как в него уложиться — §4.4 «Вес» |
| Свобода дизайна | Сводим в единую систему (тайминги, кривые, размеры, цвета), дорабатываем в рамках бренда, без радикального редизайна |
| Форматы | 16:9 FHD и 4K, 9:16, 1:1 и другие SMM (4:5, 4:3 по необходимости) |
| Парк | Все на Adobe 2026 (26.x), Windows 11 или Apple Silicon, Creative Cloud desktop и Adobe ID работают |
| Подход к плагину | **A.** Единое CEP-расширение для AE и Premiere сейчас, архитектура «под UXP»; оболочки переезжают на UXP при выполнении условий §6.2 |

### 1.1. Факты платформы

На 2026-10-02. Источники трёх видов: документация и сотрудники Adobe, отчёты разработчиков, пресса. Утверждения из отчётов разработчиков считаются гипотезами до пробных сборок S1–S11 (§3.1). Доказательная база лежит в `docs/research/2026-10-02/`.

1. **Premiere.**
   - UXP-плагины вышли из беты в 25.6 (ноябрь 2025); текущий релиз 26.5, 27.0 в публичной бете.
   - CEP по плану Adobe:
     - новые заявки в Marketplace не принимаются с декабря 2027;
     - по умолчанию выключен с декабря 2028, пользователь может включить обратно;
     - отсутствует в новых версиях с декабря 2029.

     Исключение «вне Marketplace» касается только приёма заявок. Внутренний ZXP тоже выключается по умолчанию с декабря 2028. Что будет с уже установленными версиями, Adobe не пишет.
   - ExtendScript в Premiere заморожен (новых функций нет с 23.0, поведение не меняют), но не удаляется. 29.09.2026 Adobe: «no plans to remove ExtendScript, from Pr / Ae / AME». Заметка «EOL ExtendScript в сентябре 2026» устарела.
   - Источник: <https://blog.developer.adobe.com/en/publish/2026/09/investing-in-the-future-of-creative-cloud-extensibility-uxp-comes-to-our-flagship-applications>, <https://forums.creativeclouddeveloper.com/t/12215>
2. **After Effects.**
   - UXP только в ранней документации; публичная бета обещана «к ноябрю 2026», все API помечены «с 27.0». AE 27 на Mac требует Apple Silicon и macOS 15, на Windows — Windows 11 24H2+.
   - CEP 12 (Chromium 99, Node 17.7.1) — единственный рабочий путь для HTML-панели, общей с Premiere. ScriptUI-панели в AE работают, но только в AE и без HTML. Выключение CEP по умолчанию — с декабря 2028.
   - ExtendScript в AE развивается: новые API в 26.0, 26.3, 26.5.
3. **MOGRT по скрипту возможен** (утверждение «технически невозможно» в заметке Cloud.ru Motion ошибочно):
   - AE: `Property.canAddToMotionGraphicsTemplate` / `addToMotionGraphicsTemplateAs`, `CompItem.openInEssentialGraphics` / `exportAsMotionGraphicsTemplate` (AE 15–16.1), слой с заменой медиа — `AVLayer.addToMotionGraphicsTemplateAs` (18.0), маркеры защищённых областей (`MarkerValue.protectedRegion`, 16.0);
   - Premiere ExtendScript: `Sequence.importMGT`, `TrackItem.getMGTComponent`;
   - Premiere UXP: `SequenceEditor.insertMogrtFromPath`.

   **Но пакетный экспорт по скрипту — гипотеза до пробной сборки:**
   - `exportAsMotionGraphicsTemplate` с 24.x возвращает `false` до окончания экспорта (не исправлено по 26.5);
   - в стороннем отчёте от сентября 2026 на AE 26.5 `canAdd…` возвращал `false` для всех свойств без предварительного `openInEssentialGraphics`;
   - по документации свойство добавляется скриптом только для checkbox, color, slider и source text; dropdown не документирован и проверяется в S1;
   - неудачное добавление вызывает модальное окно, поэтому всегда сначала `canAdd…`;
   - переключатели шрифта у Source Text, группы, комментарии и постер-кадр скриптом не задаются.
4. **Параметры MOGRT в Premiere.**
   - **ExtendScript.** Рабочий метод описан в ответах Adobe и сообщества на форумах, в официальном справочнике его нет; на 26.3.2/26.5 проверяется в S5; работает только для MOGRT, созданных в AE.
     - текст: JSON поля Source Text, `textEditValue` + `fontTextRunLength`;
     - цвет: `setColorValue`;
     - глобальный `JSON` может отсутствовать — нужен JSON-полифил под гардом (§10);
     - после записи панель Properties бывает с устаревшим текстом. На Pr 26.5.1 описан случай, когда устаревшим остался сам параметр (причина неизвестна). Поэтому каждое записанное значение перечитывается, расхождение считается ошибкой (§8.2).
   - **UXP в выпущенных версиях (≤ 26.5):**
     - текст MOGRT не читается и не пишется (Adobe признаёт недоработку);
     - остальные параметры — частично: разработчики читают списки, слайдеры и флажки и записывают список у MOGRT из AE, но часть значений приходит как null, имена параметров не видны, перечислить параметры нельзя (Adobe: «скоро»);
     - на вопрос о чтении и записи Adobe отвечает «в основном да» (`createKeyframe` + `createSetValueAction`);
     - запись цвета теряет синий канал (26.0.2–26.3).

     В типах `@adobe/premierepro` 27.0.0-beta (с beta.22, 14.09.2026) и в примере Adobe (только чтение) появился `MogrtText`: только однородный стиль, `setText` сводит несколько стилей к одному. Что он работает в публичной бете Premiere, Adobe не объявляла; до S9 считаем это непроверенным. Adobe целится в паритет к концу 2026, без даты. Источник: <https://forums.creativeclouddeveloper.com/t/11408>, <https://github.com/adobe/premierepro-types/pull/90>
   - **`importMGT` только перезаписывает** то, что лежит на дорожке: вставлять на свободную или новую.
   - **Слоты медиа MOGRT** (Media Replacement) в Premiere скриптом не заполняются вообще. В AE слоты экземпляра заполняются через `Property.setAlternateSource` (18.0+).
   - **Пресеты эффектов Premiere (`.prfpset`)** скриптом не применяются ни через ExtendScript, ни через UXP. Ключи UXP — только LINEAR/BEZIER/HOLD без управления кривой; корректирующие слои и маски UXP не создаёт.
5. **Ограничения MOGRT:**
   - только Classic 3D (Advanced 3D делает шаблон зависимым от установленного AE и медленным);
   - только встроенные эффекты; часть встроенных MOGRT не поддерживает, их не используем: Camera-Shake Deblur, Synthetic Aperture Color Finesse, Maxon CINEWARE, Puppet, Warp Stabilizer; без футажа через Dynamic Link и FLV;
   - без звука внутри при Responsive Time;
   - шрифты не переносятся;
   - MOGRT из более новой AE не открывается в более старом Premiere.
6. **Лицензии и обновления.** По российской прессе, с 7 июля 2026 Adobe отключила российские корпоративные подписки VIP: установленные программы отключаются не сразу, обновлений нет. Сколько они будут работать без подписки, неизвестно (выяснить в D20).
   - На этой машине Pr 26.3.2, AE 26.3, AME 26.3.2 при вышедших 26.5.x.
   - AE 2025 не установлен (остались только файлы плагинов).
   - CC Libraries и синхронизацию Adobe Fonts считаем недоступными.
7. **Урок прошлой попытки** (Cloud.ru Motion Presets). Анимации, переписанные кодом, не совпали с дизайном: потерялись маски, вложенные прекомпы, режимы наложения. **Принцип: источник правды — авторские композиции; код только параметризует и вставляет.**

## 2. Что сейчас в пакете (итоги аудита)

Офлайн-разбор всех 10 `.aep` плюс ffprobe всех медиа. Детали лежат в проекте, в `docs/research/2026-10-02/`: `audit_*.json`, `critic.json`, `research_*.json`, `verify_*.json`, `media_inventory.txt`.

- **Нулевая параметризация.** 0 элементов Essential Graphics во всех проектах. Ширины плашек подогнаны ключами Scale X под каждый текст, каждый вариант (сторона, спикер, слоган, цвет) — отдельная копия композиции.
- **Дубли:**
  - логотип — минимум 7 копий с разными белыми (#F7F7F7 / #F8F8F8 / #FFFFFF) и зелёным куба (#26D07C / #31D383); геометрия копий не сверена;
  - шапка «логотип + дескриптор «облачные и ИИ-сервисы» + бегущая штриховка» одинакова у вебинаров и курсов (термин «дескриптор» уточняется по брендбуку, D22);
  - три разных дизайна подписи спикера (титры, подкаст, полосы вебинаров);
  - рамка подкаста вручную скопирована в 13 композиций, в подкасте 9 сирот прошлых выпусков;
  - четыре перехода SMM — одна анимация в трёх цветах и вариант с логотипом.
- **Технические мины:**
  - путь 322 символа (AI-клип вебинаров, лимит Windows 260);
  - 10 имён в Mac-нормализации NFD (из-за них два WAV подкаста не находятся на Windows);
  - опорный кадр реального выпуска видим в 14 оверлеях подкаста;
  - рендерер Advanced 3D в 8 композициях;
  - таймер вебинара реверсирован (длину не поменять);
  - все проекты на устаревшем движке выражений ExtendScript. По аудиту все нынешние выражения (в SMM — 397, в курсах — 79/90, в вебинарах — 9) разбирает и JavaScript-движок, переписывать их не нужно. Работа есть по другим причинам: 390 однотипных выражений рига PATTERN_EDIT слишком тяжелы для MOGRT (риг остаётся предрендером), пустые и самоссылающиеся выражения удаляются.
- **Частоты кадров:** 24, 25 и 30 fps вперемешку. Пресеты AME вебинаров на 24 fps против композиций на 25, SMM-пресеты на 30 против 24/25.
- **Тяжёлые рендеры** — 18 файлов `.mov`, 12,9 ГБ:
  - три 10-минутных ProRes-оверлея курсов на 10 ГБ (по сути статичная рамка и 60-секундный дрейф блоков);
  - SMM-фоны 30 с по 0,4–0,5 ГБ, не бесшовные;
  - вертикальное интро подкаста в QuickTime Animation, 413 Мбит/с; в Podcast_Pack.aep исходной композиции нет (поиск исходника на Mac и T7 — D12).
- **Визуального эталона нет у большинства композиций.**
  - Рендеры есть у SMM (фоны, оверлеи, переходы), у трёх оверлеев и «Перехода» курсов (оверлей 3:2 не рендерился) и у четырёх готовых роликов подкаста (интро 16:9 и 9:16, CTA, OUTRO; у интро 9:16 нет своей композиции).
  - Не рендерились логошоты, титры, вебинары, обложки курсов, плашки и интро шортсов SMM, все 15 оверлеев и дисклеймер подкаста.
- **Шрифты:**
  - SB Sans Display записан в проектах как версия 1.000 (сохранения на Mac) и 1.002 (SMM и эта машина), SB Sans Text — 1.003;
  - метрики разных сборок могут отличаться;
  - на этой машине все 35 файлов SB Sans установлены для всех пользователей.
- **`(converted)`-файлы.**
  - Логошоты: converted новее, отличается одним слоем подложки.
  - Титры: converted — копии под конкретных спикеров без дизайнерского выхода.
  - Курсы: converted фактически продакшн-проект с недостающими файлами на `G:\`; чистый шаблон — оригинал.
  - Запись Times New Roman в их текстах, скорее всего, безвредная запись запасного шрифта; подтвердить через `app.project.usedFonts`.
- **Пакет живёт в продакшне.** Кэши `.cfa`/`.pek` доказывают, что монтажные проекты Premiere ссылаются через Dynamic Link на converted-файл курсов (медиа на `G:\`, сейчас не подключён). Рендеры пакета, вероятно, стоят в готовых монтажах. Поэтому оригиналы не переименовываются и не удаляются (§3.3).

## 3. Дорожная карта

Фазы 1–2 идут **попакетно**: сначала первый пакет (логошоты и титры) проходит весь путь и обкатывает конвейер, затем подкаст, SMM, курсы, вебинары. Первый пакет заодно строит общие узлы, которые разблокируют остальные пакеты: `CR_LOGO`, риг плашки, семейство подъёма текста, библиотеку фирменных кривых. Эти узлы проектируются по JSX-дампам всех пакетов (§3.3), чтобы стили подкаста, SMM, курсов и вебинаров сразу вошли в риг. Плагин (фаза 3) стартует, как только зафиксирован формат `library.json` и готов первый пакет.

Каждая фаза получает свой план реализации. Первым пишется план фазы 0 и первого пакета; планы следующих фаз — по итогам предыдущих.

### 3.1. Пробные сборки фазы 0

Делаются на установленных AE 26.3 и Pr 26.3.2. Если канал обновлений есть, ключевые повторяются на 26.5.

| # | Где | Что проверяем | Если «нет» |
|---|---|---|---|

### 3.2. Эталон и источник правды для пересборки

- **Эталонные рендеры.**
  - Рендерятся из копии, где сделана только перелинковка (короткие NFC/ASCII-пути к тем же файлам, без правок композиций), или на Mac.
  - Перед `aerender` скрипт проверяет, что пропавших файлов 0, иначе эталон не принимается.
  - `aerender` рендерит все ROOT-композиции: PNG в ключевые моменты и прокси в половинном разрешении.
- **Сверка с эталоном.**
  - Для сверки мастер заполняется значениями оригинала из фикстуры `<id>.ref.json` (в репозитории, в библиотеку не входит): по случаю на каждую композицию из колонки «Заменяет» §5 — тексты, фото, QR, значения переключателей (стиль, сторона, цвет, раскладка) и моменты времени.
  - Мастер рендерится в размере оригинала в те же моменты времени и сравнивается попиксельно (SSIM) и просмотром бок о бок.
  - Области, изменённые решениями §9 (D1, D2, D13, D19, D21 и др.) и обязательными правилами контракта §4.2 (Classic 3D, motion blur выключен), исключаются маской или сверяются только просмотром.
  - Значения по умолчанию с эталоном не сравниваются.
  - Для вариантов без оригинала (новые форматы, новое аутро) эталон утверждает дизайнер после первой сборки, дальше он служит регрессионным.
- **JSX-дамп.** Скрипт в AE только читает копию проекта и выгружает в JSON: композиции, слои, свойства, ключи и кривые, маски, матты, родителей, режимы наложения, стили текста. Офлайн-разбор этой сессии эвристический, поэтому числа для пересборки (тайминги, кривые, ширины) берутся только из JSX-дампа.
- **«Доктор пакета».** Скрипт находит повторяющиеся во всех пакетах проблемы гигиены: устаревший движок выражений, Advanced 3D, NFD-имена, служебные файлы, безымянные слои, личные данные и опорные кадры в шаблонах, звук в композициях, смешанные fps, небрендовые цвета.

## 4. Система шаблонов

### 4.1. Уровни доставки

| Уровень | Что | Premiere | After Effects |
|---|---|---|---|
| T1. Редактируемая графика | плашки, титры, обложки, QR-блоки, призывы, дисклеймеры, логошоты с подписью | `.mogrt` (только созданные в AE), текст и переключатели заполняются из панели; слоты медиа — перетаскиванием в Properties | композиция нужного формата из `<id>.aep` вставляется слоем; поля и слоты медиа заполняет панель |
| T2. Тяжёлая анимация без правок | фоны-паттерны, рамки с дрейфом, переходы, интро и аутро подкаста, предрендеры фиксированных подписей логошота | ProRes 4444 с альфой (или PNG в MOV по итогам S11): бесшовные петли длиной в период движения авторской композиции (по возможности 10–15 с; дрейф рамки лекции — 60 с, портал вебинара — 30 с), нарезка на интро, петлю и аутро. Ускорять движение ради короткой петли — только решением дизайнера | те же файлы |
| T3. Эффекты и ассеты | пресеты анимации, логотипы, паттерны и иконки, звуки, пресеты экспорта | клипы, звуки, рецепт «вписать в окно» (Motion), экспорт брендовым `.epr` | `.ffx` на выделенные слои, «Фирменные кривые», «Цвета», SVG/PNG, звуки, экспорт через Render Queue или aerender с шаблоном Output Module, повторяющим брендовый `.epr` (очередь AME с `.epr` — только после S10) |

В Premiere «анимация по кнопке» означает только встроенное в MOGRT, отрендеренное в клип или статичный рецепт Motion. Применение `.prfpset` и точных кривых к своим клипам в Premiere недоступно по API (§1.1).

### 4.2. Контракт шаблона

- **Имена:**
  - мастер-композиция `CR_<КОД>_<Элемент>`. Коды семейств: `LOGO`, `TTL`, `WEB`, `CRS`, `SMM`, `POD`, `TRN`, `BG`; пресеты — `CR_FX_<Имя>`. Пример: `CR_TTL_LowerThird`, `CR_TTL_TextPlate`, `CR_POD_Frame`;
  - вложенные композиции называются от имени мастера: `CR_<КОД>_<Элемент>_<Часть>`;
  - варианты форматов и зависящие от формата вложенные композиции — с суффиксом формата (`_16x9`, `_16x9_4K`, `_9x16`, `_1x1`), во всех именах композиций шаблона — суффикс версии (`_v3`). Ставит их конвейер (§4.4);
  - уникальные имена всех элементов проекта: AE допускает дубли, а выражения `comp("…")` цепляются за первый попавшийся.
- **Структура.** Мастер плоский: редактируемые и раскладочные слои на верхнем уровне. Вложенные прекомпы — только для частей, не зависящих от формата; иначе конвейер дублирует их для каждого варианта.
- **Тексты:**
  - верхнеуровневые слои `TXT_<ПОЛЕ>`, **один стиль на поле**: этого требуют и запись через ExtendScript, и будущий UXP `MogrtText`;
  - point-текст, никаких пустых абзацев для отступа;
  - если у каждой строки своя плашка, каждая строка — отдельное поле и отдельный слой (`TXT_LINE1…TXT_LINE3`), пустая строка скрывает свою плашку. Явные переносы внутри поля — только там, где у строк нет своих плашек (плашка общая на весь блок или её нет).
- **Контролы:**
  - слой `CTRL`, не больше 8 контролов (dropdown, checkbox, slider с границами); текстовые поля, слоты медиа, флажок QA и служебный слайдер «Длительность» в лимит не входят;
  - внутренние имена ASCII, отображаемые в Essential Graphics — по-русски;
  - point- и angle-контролы не используем;
  - цвет — только выпадающим списком палитры, без color picker;
  - Source Text без управления шрифтом: шрифт закреплён за стилем шаблона.
- **Вёрстка:**
  - плашки и окна подстраиваются под текст через `sourceRectAtTime`, замер в момент покоя или по скрытой MEASURE-копии, чтобы размер не дрожал во время анимации текста;
  - отступы считаются выражениями от размера кадра; кегли под формат выставляет конвейер (§4.4).
- **Время:**
  - маркеры `in`/`out`;
  - `fit: rdt` — Responsive Design–Time, только для шаблонов со статичной серединой: защищённые интро и аутро, середина растягивается;
  - `fit: trim` — шаблоны с движением в середине (таймер, бегущая штриховка, видео в слотах) делаются без RDT. Слот, который принимает видео, делает шаблон `trim`; слоты только для фото и QR на `fit` не влияют. Композиция максимальной длины (таймер — 15 мин плюс аутро), панель обрезает клип до нужной длины. Если нужно аутро в конце клипа, панель пишет реальную длину клипа в служебный слайдер `CTRL` «Длительность (служебное, не менять)». Он выведен в Essential Graphics, иначе панель его не запишет, но в форме панели не показывается; выражения считают время от него. Длина таймера = минуты × 60 с + аутро: поле «минуты» задаёт и контрол, и длину вставки (`drivesDuration`);
  - внутри мастера нет удержаний через time remap и обратного воспроизведения, у слоёв нулевой старт и растяжение 100 %. На слое экземпляра в композиции пользователя длина подгоняется механизмом из S3.
- **Медиа:** фото, QR и видео через Media Replacement. Футажей вне слотов нет; опорные кадры — только guide-слоями в рабочих копиях.
- **Техника:**
  - Classic 3D;
  - только встроенные эффекты, кроме неподдерживаемых в MOGRT (§1.1 п. 5); без футажа через Dynamic Link и FLV;
  - выражения пишутся под JavaScript-движок и проверяются в обоих движках (QA-гейт §4.4);
  - обращения к эффектам по индексу или match name (русский интерфейс AE ломает обращения по имени);
  - без звука внутри;
  - motion blur выключен по умолчанию;
  - нативные размеры: текст 100 %, реальные кегли, никаких масштабирующих нулей.
- **Шрифты** по PostScript-именам: `SBSansDisplay-Semibold` (строчная «b»), `SBSansDisplay-Regular`, `SBSansDisplay-Bold`, `SBSansText-Regular`.
- **Цветовой патч** в каждом мастере — обычный слой, не guide. Он включается скрытым флажком QA на `CTRL`, который не выводится в Essential Graphics и не считается в лимит. Конвейер включает патч для QA-рендера и QA-экспорта MOGRT и выключает его в релизных файлах.
- **Файлы:**
  - файлы библиотеки и шаблонов — только ASCII (латиница, цифры, `_`, `-`), не длиннее 64 символов;
  - один элемент на `.aep` (со всеми форматами элемента), сохранение в AE 26;
  - NFC — требование к рабочим копиям пакетов, где кириллица остаётся.

### 4.3. Форматы

- Один мастер на шаблон. Конвейер создаёт варианты (§4.4, шаг 1): 16:9 FHD, 16:9 4K, 9:16, 1:1; 4:5 и 4:3 — по запросу.
- Где вертикаль требует другой раскладки (логошот, анонс), мастер переключает раскладку по пропорции кадра.
- **Premiere.** MOGRT, созданный в AE, не подстраивается под секвенцию. Поэтому плагин читает размер активной секвенции и вставляет MOGRT нужного варианта.
- **After Effects.** В `<id>.aep` лежат композиции всех форматов элемента. `.aep` импортируется один раз на `id@версия`, а слоем вставляется композиция варианта, выбранного по размеру активной композиции (`aeComp` в `variants[]`).
- В обоих хостах есть ручной переключатель формата. Если варианта нет, плагин предлагает ближайший.

### 4.4. Библиотека и конвейер сборки

```text
<корень библиотеки>/                    Win: C:\ProgramData\CloudRuBrandKit\library\   Mac: /Users/Shared/CloudRuBrandKit/library/
  library.json
  items/<id>/<id>_<формат>_v<N>.mogrt … <id>_v<N>.aep preview.mp4 poster.jpg
  presets/*.ffx      media/*.mov      stills/*.svg|png      sfx/*.wav      ame/*.epr      om/*.aom
  prproj/CR_Templates.prproj           клип корректирующего слоя (D11), стиль субтитров «CR Субтитры» (D25)
```

**Источник и каталог.**
- **Источник** — `library.src.json` в репозитории. Его правят руками: элементы, поля, форматы, контролы Essential Graphics.
- **Каталог** — `library.json`. Его пишет конвейер с файлами, `sha256` и версиями; руками не правится.

**Схема `library.json`** (фиксируется в фазе 0):
- **Верхний уровень:** `libraryVersion` (calver), `minPluginVersion`.
- **Элемент:**
  - `id`, `title_ru`, `category`, `tier`, `hosts`, `version`;
  - `fit` (`rdt` или `trim`, §4.2);
  - `cutFrame` у переходов (первый кадр полного перекрытия);
  - `windows[]` у рамок (прямоугольники окон по вариантам);
  - `requiredFonts` (PostScript-имя и эталонная сборка);
  - `duration` (интро, аутро, удержание по умолчанию);
  - `loop` (период петли в кадрах).
- **`variants[]`:**
  - `aspect`, `w`, `h`, `fps`;
  - `file` (MOGRT или медиа), `aeComp` (композиция варианта в `.aep`);
  - `options` (значения переключателей предрендера: цвет, логотип, подложка);
  - `parts` (интро, петля, аутро у T2);
  - `sha256`, `minHostVersion`.
- **`fields[]`:**
  - `key` (ASCII-ключ поля), `label_ru`, `type`;
  - `egpName` — отображаемое (русское) имя свойства в Essential Graphics: по нему адаптер Premiere ищет параметр (`getParamForDisplayName`), в мосте оно передаётся в ASCII-JSON с экранированием;
  - `egpIndex` — для будущего UXP;
  - `default`, `maxLen`;
  - `options[]` (подписи и индексы пунктов списка, с 1), `min`/`max` у слайдеров;
  - `drivesDuration` (поле задаёт длину вставки, как минуты таймера);
  - `service` — служебное поле (слайдер «Длительность»): панель пишет его сама после обрезки и не показывает ни в форме, ни в проверке возможностей;
  - `hosts` (например, слот медиа заполняется автоматически только в AE).
- **`companions[]`:**
  - `ref` (id элемента-компаньона);
  - `kind`: `music`, `sfx` или `video`;
  - `placement`: `in`, `out` или `under`;
  - `default` — включён ли компаньон по умолчанию: `music` и `sfx` — по D14 (галочки формы); `video` ставится всегда, если у элемента нет своего переключателя (у рамки подкаста — поле «размытие», §5).

  Составной элемент («T1 + фон T2», «кадр + петля») описывается основным элементом и компаньонами со своим `tier`.

Матрица вариантов (элементы × форматы × опции) генерируется из `library.src.json`: ~25 мастеров дают 100+ файлов, поэтому каждый вариант собирается и проверяется только скриптом.

**Вес.** Нынешние рендеры весят 12,9 ГБ (18 файлов `.mov`). Вес новой библиотеки считается в фазе 0 по матрице T2 и замеренным битрейтам этого пакета: ProRes 4444 — около 15 МБ/с на кадр ~2 Мп, у 4K до вчетверо больше. Одни фоны-петли во всех форматах с обеими подложками дали бы порядка 6 ГБ. Бюджет веса установщика утверждается в фазе 0 (D24) и проверяется в приёмочной части QA-гейта. Чтобы уложиться:
- 4K — только там, где он нужен;
- подложку #222222 под альфа-петлю ставит панель (стилл), а не отдельный вариант петли;
- петли минимальной бесшовной длины;
- кодек петель — по итогам S11.

**Версии MOGRT** — по итогам S6. По умолчанию:
- версия в именах композиций и файлов (`_v3`) и новый capsuleID;
- уже вставленные в проекты экземпляры не обновляются, обе версии сосуществуют без конфликта;
- новая версия заменяет старую в каталоге панели.

**Конвейер** — одна команда. Node управляет, AE исполняет JSX. Выходы рендера идут в ASCII-путь, потому что в AE 26.1+ есть баг с не-ASCII путями вывода. Ручная настройка Essential Graphics (группы, постер; выпадающие списки и другие свойства — только если S1 не подтвердила их добавление скриптом) делается один раз в мастер-композиции рабочего проекта до шага 1 и переживает пересборку. Рабочий проект конвейер не сохраняет: для каждого элемента он открывается заново, шаги 1–3 идут в открытой копии, результат сохраняется только как `<id>_v<N>.aep`.

1. **Варианты.** Для каждого формата матрицы мастер-композиция рабочего проекта дублируется под размер кадра (`CR_<КОД>_<Элемент>_<формат>`); зависящие от формата вложенные композиции дублируются вместе с ней и получают суффикс формата, а слои и выражения варианта конвейер переводит на эти дубли. Кегли конвейер выставляет скриптом в стиле текста каждого варианта (k = min(ширина, высота) / 1080), отступы считают выражения от размера кадра; слой текста остаётся 100 %.
2. **Нарезка.** `reduceProject` по композициям элемента:
   - во все имена композиций ставится суффикс версии;
   - выражения проверяются: ссылки только на композиции своей версии и своего формата (или на общие, не зависящие от формата), внешних нет.
3. **Контролы.** Essential Graphics по описанию из `library.src.json`:
   - для каждой композиции варианта: сначала `openInEssentialGraphics`, затем `canAdd…`, потом добавление;
   - добавляются только отсутствующие свойства (сверка по имени), поэтому повторный прогон ничего не дублирует;
   - защищённые области ставятся маркерами;
   - затем результат шагов 1–3 сохраняется как одноэлементный `<id>_v<N>.aep` со всеми форматами (Save As; рабочий проект не меняется). Так `.aep` попадает в библиотеку с Essential Properties, даже если MOGRT у элемента нет или он экспортируется вручную.
4. **Экспорт MOGRT** по вариантам, строго по одному: сохранение → `openInEssentialGraphics` → экспорт → ожидание стабильного файла. Новая версия получает новый capsuleID (механизм — S6).
5. **Рендеры T2 и превью.** `aerender`:
   - что рендерится: петли, переходы, предрендеры фиксированных подписей логошота, интро и аутро подкаста;
   - формат: ProRes 4444 без звука (или кодек по S11), таймкод 00:00:00:00;
   - бесшовность: период петли — целое число кадров N; рендерится N + 1 кадр, кадр N сравнивается с кадром 0 (SSIM ≈ 1). В файле ровно N кадров (кадры 0…N−1, `loop`): кадр N в файл не входит, иначе на стыке будет повтор кадра;
   - превью: 480 px MP4 и постер.
6. **QA-гейт, автоматическая часть** (в конвейере, на каждую сборку):
   - рендерер Classic 3D;
   - эффекты только встроенные и поддерживаемые в MOGRT (§1.1 п. 5); нет футажа через Dynamic Link и FLV;
   - контракт §4.2 проверяется скриптом (расширенный `G.tplProblems`): уникальные имена, слои `TXT_` и `CTRL`, не больше 8 контролов на `CTRL` (без флажка QA и слайдера «Длительность»), внутри мастера нулевой старт и растяжение 100 %, motion blur выключен, один стиль на поле;
   - выражения без ошибок в обоих движках: проект переключается на Legacy ExtendScript и на JavaScript, ключевые кадры рендерятся в обоих;
   - шрифты из списка (PostScript-имя и эталонная сборка);
   - нет звука и футажа вне слотов;
   - имена файлов ASCII ≤ 64 символов;
   - fps и размеры по канону;
   - `sha256`;
   - сверка с эталоном по §3.2;
   - цветовой патч: ΔE между рендером AE и T2-рендером;
   - бесшовность петель.
7. **QA-гейт, приёмочная часть** (на каждый релиз библиотеки, в Premiere: в фазе 2 — тестовым скриптом ExtendScript, с фазы 3 — живыми прогонами §8.3):
   - ΔE патча в MOGRT;
   - замер воспроизведения выборки на самой слабой машине;
   - вес в бюджете D24.

Пороги фиксируются в фазе 0 вместе с контрактом. Исходно: ΔE2000 ≤ 2; SSIM ≥ 0,98 на неизменённых областях. Бюджет производительности задаётся числом после повтора S8 на первых мастерах первого пакета, до первой приёмки релиза.

## 6. Архитектура плагина

**Одно CEP-расширение** (`ru.cloud.brandkit`, хосты AEFT и PPRO, минимальные версии 26.0, тестовая база AE 26.3 и Pr 26.3.2; CSXS 11+ на CEP 12; Node включён).

- **Интерфейс:** TypeScript + Vite под Chromium 99 (движок CEP 12), Preact; CSS из генератора бренд-токенов. Каркас (Bolt CEP или свой конфиг Vite) выбирается в фазе 0 по двум критериям: мульти-хост `CSXS/manifest.xml` (AEFT + PPRO) и сборка подписанного ZXP. Интерфейс знает только API ядра: никаких прямых вызовов CSInterface или Node.
- **Ядро** — чистый TypeScript с внедряемыми сервисами: файлы, процессы (в CEP — Node `child_process`) и хост:
  - чтение и валидация `library.json`;
  - выбор варианта по кадру;
  - сопоставление полей формы с контролами;
  - проверка шрифтов в Premiere (через внедрённый файловый сервис: Node-скан папок шрифтов и таблиц OpenType);
  - проверки версий и путей;
  - запоминание значений полей;
  - логирование.
- **Мост.** Единая точка `host.call()`:
  - аргументы ASCII-JSON (кириллица иначе ломается в `evalScript` на Windows);
  - последовательная очередь (ExtendScript однопоточный) и таймауты;
  - повтор при холодном старте только для чтения. Изменяющие вызовы не повторяются никогда — при таймауте опрашивается состояние. Единственное исключение — одна повторная вставка MOGRT, если проверка показала, что клип не появился (§6.1): изменения не было, и повтор его не дублирует;
  - один шаг отмены на клик, где хост это позволяет (S5 считает реальные шаги);
  - проверка возможностей (capability check). Для каждого поля определяется режим: «заполняет панель» или «заполните в Properties после вставки» — поле видно, неактивно, с подсказкой. Целиком скрываются только элементы, которые хост не умеет вставлять (`.ffx`, «Фирменные кривые» и «Цвета» в Premiere).
- **Адаптеры** (ES3 с JSON-полифилом, общая обёртка `_wrap` и контракт `{ok, data, error}`; загружаются по `appName`):
  - `getContext` — хост, версия, активная композиция или секвенция, кадр, fps, время, выделение; в AE также рабочее пространство, линеаризация, глубина цвета и режим управления цветом проекта;
  - `insertItem(variant, fields, options)`;
  - `setFields(target, fields)` — с чтением назад каждого записанного значения;
  - `applyPreset(ffx)` (AE);
  - `applyBrandEase(profile)` (AE);
  - `applyColor(token)` (AE);
  - `fitToWindow(recipe)` (Pr);
  - `importAsset(path, target)`;
  - `exportWithPreset(epr)`. Premiere — `exportAsMediaDirect`, очередь AME через `app.encoder.encodeSequence` проверяется в S7. AE — Render Queue из адаптера или aerender, который ядро запускает через внедрённый сервис процессов по сохранённому проекту; оба берут шаблон Output Module по имени из настроек AE (§8.1); очередь AME с `.epr` только после S10;
  - `checkFonts(psNames)` (AE) — через `app.fonts`, с версией сборки (`FontObject.version`);
  - `diag()`.

### 6.1. Вставка по клику

**Premiere, элемент T1 (MOGRT):**
1. Контекст: размер кадра даёт вариант, fps, плейхед. Длина вставки — одинаково для `trim` и `rdt`: поле с `drivesDuration`, если оно есть и активно (например, минуты включённого таймера × 60 с + аутро), иначе `duration` элемента (удержание по умолчанию).
2. Проверки: шрифты (наличие и сборка), fps шаблона и секвенции, проект сохранён.
3. Выбор дорожек. `importMGT` перезаписывает сразу и ставит клип с длиной MOGRT по умолчанию, а обрезка идёт позже. Поэтому дорожка для MOGRT проверяется свободной на интервале от плейхеда до большей из двух длин: длины вставки и длины MOGRT по умолчанию (по итогам S5; для `trim` — длина композиции максимальной длины). Свободные дорожки над записью — для видеокомпаньонов, выше них — для MOGRT. При нехватке добавляются новые дорожки; это делается через QE DOM, вызов изолирован.
4. Вставка MOGRT на выбранную дорожку.
5. Проверка, что клип появился на нужной дорожке в нужное время. Если его нет, допустима одна повторная вставка: изменения не было. Иначе ошибка «вставка не выполнена» (§8.2), больше ничего не ставится.
6. Длительность: `rdt` — длина по итогам S5; `trim` — клип обрезается до длины вставки.
7. Видеокомпаньоны (фон T2 экрана вебинара, корректирующий клип размытия подкаста) — на выбранные дорожки под MOGRT, по длине получившегося клипа.
8. Запись полей с чтением назад (§8.2 при расхождении).
9. Звук по галочкам «Музыка» и «Звуковые эффекты» — на свободные аудиодорожки по `placement`: `in` — к началу клипа, `out` — к концу, `under` — на всю длину.
10. Выделение клипа. Для полей в режиме «заполните в Properties» — подсказка заполнить их в Properties; для слотов медиа — перетащить фото, QR или визуал в Properties.

**Premiere, элементы T2/T3 (файлы):**
- **Шаблонный проект.** `prproj/CR_Templates.prproj` импортируется один раз на версию библиотеки в бин `Cloud.ru BrandKit`. Стиль субтитров «CR Субтитры» только появляется в бине и на дорожку не ставится; клип размытия берётся из бина как видеокомпаньон (шаг 7).
- **Импорт.** Файл копируется в папку `Cloud.ru BrandKit/<id>@<версия>/` рядом с проектом, оттуда импортируется в бин `Cloud.ru BrandKit` без дублей и ставится на свободную дорожку на плейхед.
- **Петли** повторяются встык до нужной длины (поле «длительность» или до конца выделенного диапазона). Подложку #222222 при необходимости панель ставит стиллом под петлю.
- **Переходы** ставятся так, чтобы маркер полного перекрытия совпал с ближайшей к плейхеду склейкой.
- **Рецепт «вписать в окно»** задаёт масштаб и позицию Motion у выделенного клипа под окно рамки (`windows[]`). В раскладке «со спикером» панель спрашивает, какое окно заполнить:
  - окно экрана — в пропорции записи (D9), обрезка не нужна;
  - окно спикера портретное: запись 16:9 масштабируется по высоте окна, излишек закрывают рамка и клип экрана, если клип спикера лежит на дорожке ниже клипа экрана;
  - клипы между дорожками панель не переносит: если клип спикера лежит выше клипа экрана, панель добавляет обрезку (Crop через QE, проверяется в S7).

**After Effects:**
1. Контекст: активная композиция, текущее время, выделение, рабочее пространство и управление цветом.
2. Проверки:
   - шрифты (наличие и сборка), версия хоста;
   - проект сохранён — нужен путь для папки `Cloud.ru BrandKit/` рядом с файлом проекта;
   - рабочее пространство, линеаризация, глубина цвета или режим управления цветом (OCIO/ACES) отличаются от эталона — настроек проекта сборки (Rec.709 Gamma 2.4, управление цветом Adobe) — предупреждение, без переключения: смена `workingSpace` скриптом вызывает модальное окно;
   - движок выражений проекта показывается в диагностике, переключать не предлагается: шаблоны проверены в обоих движках, а переключение может сломать выражения пользователя.
3. Импорт `<id>_v<N>.aep` один раз на `id@версия` в папку `Cloud.ru BrandKit` панели Project (метка в комментарии). Футаж шаблона копируется в `Cloud.ru BrandKit/<id>@<версия>/` рядом с файлом проекта и перелинковывается (`FootageItem.replace`). Имена композиций уже содержат версию, панель ничего не переименовывает.
4. Композиция варианта (`aeComp`, по размеру активной композиции) добавляется слоем на текущее время.
5. Поля пишутся в Essential Properties, слоты медиа — через `setAlternateSource`. Длина — по тому же правилу, что в Premiere (шаг 1), подгоняется механизмом из S3 по `fit`.
6. Компаньоны:
   - видеокомпаньон T2 (фон экрана вебинара) — слоем под слоем шаблона на его длину, с повтором по правилу «Петли T2»;
   - звук — отдельным слоем при включённой галочке, по `placement`, как в Premiere;
   - размытие полей подкаста — корректирующим слоем в композиции пользователя под слоем рамки. Внутри вложенной композиции без Collapse Transformations корректирующий слой действует только на её собственные слои.
7. Пресеты `.ffx`: выставить выделение и время, затем `applyPreset`.

Особые случаи AE:
- **Петли T2** — футаж с повтором (Interpret Footage → Loop) до длины поля «длительность» или рабочей области; подложку #222222 при необходимости панель ставит стиллом под петлёй.
- **Переходы** — маркером полного перекрытия на текущее время.

**Переносимость проектов.**
- **Медиафайлы T2/T3** (петли, звуки, стиллы) и **футаж внутри AE-шаблонов** (заглушки слотов и QR по умолчанию; другого футажа в шаблонах нет, §4.2 «Медиа») копируются в `Cloud.ru BrandKit/<id>@<версия>/` рядом с проектом и перелинковываются туда.
- **Композиции AE-шаблона** встраиваются в проект, но их футаж остаётся ссылкой на файл. Без копирования у коллеги, особенно на другой ОС, он окажется пропавшим: путь библиотеки на Windows и Mac разный.
- **MOGRT** Premiere распаковывает в папку «Motion Graphics Template Media» (Project Settings → Scratch Disks, по умолчанию «Same as Project»). Эту папку переносят вместе с проектом. Путь к проекту держат коротким: длиннее 260 символов даёт ошибку «Motion Graphics Template is corrupt».

## 8. Установка, ошибки, тестирование

### 8.1. Установка и обновление

- **Подписанный `.zxp`.** Самоподписанный сертификат через ZXPSignCmd 4.1.3 с меткой времени. CEP 12 бывает, что игнорирует PlayerDebugMode (отчёт по AE 26.3).
- **Установщик** `install.cmd` / `install.ps1` (Windows) и `install.command` (Mac):
  - отказывается работать при открытых AE или Premiere;
  - распаковывает расширение в пользовательскую папку CEP;
  - ставит библиотеку в общий ASCII-путь (§4.4);
  - кладёт копии MOGRT плоско в пользовательскую папку Local Templates (Win: `%APPDATA%\Adobe\Common\Motion Graphics Templates`, Mac: `~/Library/Application Support/Adobe/Common/Motion Graphics Templates`) с ASCII-кодом семейства в начале имени (например, `TTL_LowerThird_16x9_v3.mogrt`, §4.2 «Файлы»): штатная панель Graphics Templates не видит подпапки. При обновлении удаляет оттуда свои копии прошлых версий (по списку из прежнего `library.json`); вставленные экземпляры от них не зависят;
  - по желанию добавляет `.epr` в пользовательские пресеты AME;
  - чистит `cep_cache`;
  - печатает версии.

  Админ-права, Creative Cloud desktop и Adobe ID не нужны. Расширение CEP и копии MOGRT ставятся в профиль пользователя, поэтому установщик запускают в каждой учётной записи, где работают с панелью.
- **Шаблон Output Module** для экспорта из AE. Файл `.aom` скриптом не загрузить: шаблон в настройках AE либо создаёт скрипт (`setSettings` + `saveAsTemplate`), либо пользователь загружает файл вручную (Edit → Templates → Output Module → Load); способ выбирается в S10. Панель ищет шаблон по имени в `OutputModule.templates`. Если его нет: при способе «скрипт» панель создаёт шаблон и продолжает экспорт, при ручном способе вместо экспорта показывает инструкцию по загрузке `.aom` из `om/`.
- **Права на папку библиотеки.** При первом создании папки установщик открывает её на запись всем пользователям машины:
  - Windows: `icacls "C:\ProgramData\CloudRuBrandKit" /grant "*S-1-5-32-545:(OI)(CI)M"` (в кавычках строка работает и в cmd, и в PowerShell);
  - Mac: после каждой записи — `find /Users/Shared/CloudRuBrandKit -user "$(id -u)" -exec chmod a+rwX {} +` (только свои файлы: chmod может выполнить лишь владелец); ошибки на чужих файлах установку не прерывают.

  Иначе из другой учётной записи той же машины обновить библиотеку без админа нельзя.
- **Mac.** `install.command`, полученный через браузер или мессенджер, помечен карантином и двойным щелчком не запускается. На macOS 15+ ПКМ → «Открыть» карантин не обходит, а «Всё равно открыть» в «Конфиденциальность и безопасность» требует пароль администратора. Поэтому в инструкции — запуск из Терминала: `bash install.command` (Gatekeeper проверяет только запуск двойным щелчком, админ не нужен); установщик снимает карантин со своих файлов (`xattr -dr com.apple.quarantine`). Альтернатива — раздача через MDM или SMB без карантина. Проверяется в критерии фазы 3 «чистая установка с нуля».
- **Версии:** плагин semver, библиотека calver; обе видны в панели. Обновление — новый установщик.
- **Шрифты.**
  - SB Sans в пакет не кладутся. IT ставит одну и ту же сборку «для всех пользователей» на всех машинах; разные сборки могут сдвинуть автоплашки.
  - Эталонная сборка записана в `tokens.json`. Её выбирают в фазе 0 по итогам D20 и сравнения метрик 1.000 и 1.002.
  - Плагин проверяет наличие и версию сборки: AE — `FontObject.version`, Premiere — версия из таблицы `name`. Нет шрифта — отказ и ссылка на инструкцию; другая сборка — предупреждение без блокировки.
- **Сборка релиза** не содержит симлинков, `.DS_Store`, `__MACOSX`, `._*` и `.debug`.

### 8.2. Ошибки и диагностика

- Ответ хоста `{ok, data, error{code, message}}`: пользователю понятное русское сообщение, в лог — код.
- Явные отказы до вставки:
  - нет активной композиции или секвенции;
  - проект не сохранён;
  - нет шрифта для текстового шаблона;
  - версия хоста ниже минимальной;
  - нет варианта под формат (предложить ближайший);
  - путь слишком длинный.
- **Вставка не выполнена.** Клип не появился и после одной повторной попытки (§6.1) — ошибка с кодом. Компаньоны, поля и звук ставятся только после успешной вставки MOGRT, поэтому таймлайн не меняется. Исключение — пустые дорожки, добавленные на шаге 3 §6.1: они остаются, панель упоминает их в сообщении.
- **Значение не прочиталось назад.** Клип остаётся на таймлайне выделенным. Панель перечисляет незаписанные поля и предлагает «Отменить вставку» или «Заполнить в Properties». Автоматический повтор и откат не выполняются.
- Никогда не действовать на «первую попавшуюся композицию».
- Логи: JSONL по дням, ротация 7 дней или 5 МБ. Локально: `%LOCALAPPDATA%\CloudRuBrandKit\logs` или `~/Library/Logs/CloudRuBrandKit`. Внешней телеметрии нет.

### 8.3. Тестирование

- **Юнит (vitest):** `library.json`, выбор варианта по кадру, сопоставление полей, нормализация путей, ограничения версий, проверка возможностей.
- **Код хоста:** ES3-линтер и мок AE из ae-motion-live, минимальный мок Premiere.
- **QA-гейт библиотеки** (§4.4): автоматическая часть на каждую сборку, приёмочная — на каждый релиз.
- **Живые сквозные прогоны через CDP** на своих портах: 8094 для AE, 8096 для Premiere; занятые порты 8088, 8092, 8098–8100 не трогаем.

  - каждый `.ffx`;
  - каждый экспорт;
  - перенос проекта со вставками на другую ОС.
- **Установка** на чистых Windows и Mac.
- **Пилот** с 2–3 монтажёрами.
